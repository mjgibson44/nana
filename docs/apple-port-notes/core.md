# "Word" (repo: nana) — Pure Game Core Technical Report for Swift Port

All game logic lives in `/home/user/nana/src/game/` and is deliberately pure TypeScript with no DOM/React dependencies except where noted (src/game/types.ts:1-5). Files: types.ts, board.ts, generator.ts, modes.ts, rng.ts, levels.ts, placement.ts, setups.ts, stats.ts, tutorial.ts, onboarding.ts, sounds.ts, dictionary.ts, commonWords.ts, battle.ts (battle.ts was not in the requested list but is core: tile stream, referee, join codes — read fully and covered here).

## 1. Data Model

- **CellKey** = string `"row,col"` produced by `keyOf(row, col)` → `` `${row},${col}` `` (src/game/types.ts:49-51) and parsed by `parseKey` splitting on the first comma (types.ts:53-56). String keys chosen explicitly for JSON serializability / wire transfer (types.ts:7-8).
- **TileMap** = `Record<CellKey, string>` — sparse board; only occupied cells present; values are lowercase letters (types.ts:11-12). Coordinates may go negative (types.ts:22-25); the string keys handle that (e.g. `"-5,16"`, levels.test.ts:37).
- **Direction** = `'across' | 'down'` (types.ts:14). **Cell** = `{row, col}` (types.ts:16-19).
- **Bounds** = `{minRow, minCol, maxRow, maxCol}`, inclusive on all four sides (types.ts:26-31). `asBounds(size)` accepts a plain number N as shorthand for `{0,0,N-1,N-1}` (types.ts:37-41); `inBounds` is a simple rect test (types.ts:43-47).
- **Board sizing**: `BOARD_SIZE = 33` starting square (src/game/levels.ts:18), `GROW_MARGIN = 8` (levels.ts:25 — equals MAX word length). `boardBounds(board)` returns the 33×33 start rect expanded so every tile has ≥8 empty cells beyond it on every side; min/max can go negative (levels.ts:33-46).
- **Pile/rack model**: the rack is a plain `readonly string[]` of letters; picks reference letters by rack index. `Pick = {letter: string | null, rackIndex: number}` where `letter: null` + `rackIndex: GAP (= -1)` is a "gap tile" — a deliberate hole that must land on an existing board letter (src/game/placement.ts:5-14). `PlacementStep = {key, letter, rackIndex}` (placement.ts:18-22). `PlacementPlan = {steps, unfilledGaps, complete}` (placement.ts:24-34).
- **WordRun** = `{word, direction, cells: CellKey[], valid}` — a maximal horizontal/vertical run of ≥2 adjacent letters (src/game/board.ts:8-13). `BoardValidation` = `{runs, invalidRuns, isolatedTiles, disconnectedTiles, connected, tileCount, ok}` (board.ts:15-31).
- **Battle state** (src/game/battle.ts:20-66): `BattlePhase = 'lobby'|'playing'|'finished'`; `BattlePlayer = {id, name, host, score, buried, connected, left, waiting, tiles, outOrder: number|null}`; `BattleState = {phase, players, game, winnerId}`. All pure and serializable by design — networking layer moves these values between browsers (battle.ts:11-18).
- **Puzzle** = `{letters: string[], solution: TileMap | null, sourceWords: string[]}` (src/game/generator.ts:17-25). `solution` is a known-good arrangement (proof of solvability); null only on the fallback path.
- Everything is JSON-serializable plain data: TileMaps are string→string dicts; no classes anywhere in the core.

## 2. Board Rules Engine (board.ts)

- `MIN_WORD_LENGTH = 3` — two-letter runs never count even if in the dictionary (board.ts:4-5, 121-122; test board.test.ts:95-101).
- `extractRuns(tiles)`: for each occupied cell whose left (resp. above) neighbor is empty, walk right (resp. down) collecting cells; runs of length ≥2 emitted with concatenated word (board.ts:34-75). Note: emitted order follows `Object.keys(tiles)` insertion order.
- `components(tiles)`: DFS-ish (queue used as a stack via `pop()`, board.ts:91) 4-neighbor flood fill; groups returned **sorted largest first** (board.ts:109). Ties keep traversal order (JS sort is stable).
- `validateBoard(tiles, dictionary)` (board.ts:117-151): run.valid = `word.length >= 3 && dictionary.has(word)`; `isolatedTiles` = tiles in no ≥2 run; `disconnectedTiles` = every group after the largest, flattened (board.ts:133-134); `ok` = tileCount>0 && no invalid runs && no isolated tiles && no disconnected tiles (board.ts:145-150). Empty board: connected=true but ok=false (board.test.ts:89-93).

## 3. Generator (generator.ts) and Determinism Contract

**Algorithm** — build an actual hidden crossword from common words, then hand the player its letters shuffled; guarantees ≥1 fully valid, fully connected arrangement by construction (generator.ts:4-15).

- Word constraints: `MIN_WORD_LEN=3`, `MAX_WORD_LEN=8` (generator.ts:27-28); `usableWords` filters pool to `3..8` letters matching `/^[a-z]+$/` (generator.ts:418-422).
- Indexes: `byLetter: Map<letter, word[]>` — for each usable word, for each `new Set(word)` distinct letter (insertion = first-occurrence order), push word; `byLength: Map<len, word[]>` (generator.ts:439-450). **Bucket array order = word-pool order** — this order is consumed by `pick()` and is determinism-relevant.
- `usableLengths(remaining)`: candidate word lengths 3..8 where `rest = remaining - (len-1)` is `0` or `>= MIN_WORD_LEN-1` (=2) — a crossing word of length L adds L−1 tiles (generator.ts:43-53).
- `canPlace(grid, word, crossRow, crossCol, crossIndex, dir)` (generator.ts:67-100): word laid so its crossIndex-th letter sits on the anchor; cell before start and after end must be empty; every non-cross cell must be empty AND have both lateral neighbors empty; the cross cell must already hold exactly `word[i]`. This forbids all accidental adjacencies — every run on a built grid is exactly one chosen word.
- `tryBuild(byLetter, byLength, tileCount, rng, maxSpan=Infinity)` (generator.ts:113-202): seed word length picked from `usableLengths(tileCount+1)` filtered to `<= tileCount && <= maxSpan`, preferring lengths ≥5 (generator.ts:122-127); seed word `pick(seedPool, rng)` placed at (0,0) across (generator.ts:131-132). Loop until tiles==tileCount or **500 failures**: pick a random anchor cell from `Object.keys(state.grid)`, pick a random candidate word from `byLetter[anchorLetter]`, reject if its length not in `usableLengths(tileCount - tiles)`, pick a random occurrence of the anchor letter as crossIndex, direction = `rng() < 0.5 ? 'across' : 'down'`, `canPlace`, reject if it would stretch the bounding box past `maxSpan` (generator.ts:143-198). Returns state only if exactly tileCount tiles.
- `normalize(grid)` shifts so min occupied row/col is (0,0) (generator.ts:205-220).
- `generatePuzzle(wordPool, tileCount=20, rng=Math.random, maxSpan?)` (generator.ts:429-473): throws on empty pool or tileCount<3; tries `tryBuild` **100 attempts** (400 when maxSpan set, generator.ts:453); on success returns `{letters: shuffle(Object.values(solution), rng), solution: normalize(built.grid), sourceWords}`. On total failure: `fallbackSample` — up to **200 attempts** sampling disjoint words whose lengths sum exactly to tileCount (rest must be 0 or ≥3) (generator.ts:227-255, 466-472); solution=null.
- `extendPuzzle(board, size, wordPool, tileCount, rng=Math.random)` (generator.ts:361-397): grows exactly tileCount *new* tiles onto an existing board via `tryExtend` (**800-failure cap per attempt**, **200 attempts**, generator.ts:293-350, 385): same anchor/word/crossIndex/dir mechanics as tryBuild, plus `fitsBoard` bounds check (generator.ts:273-287); new letters = keys of built grid not in original board, returned `shuffle`d, with `solution = built.grid` (generator.ts:388-391). Empty board or tileCount<2 → `standalone` (generator.ts:369-373): tileCount<3 draws single letters via `sampleLetters` (random word, then random letter of it — 2 rng calls per letter, generator.ts:263-270); else a fresh `generatePuzzle` (solution=null in extend's return, generator.ts:404-416). Congested board that can't grow → `standalone` fallback (generator.ts:396).
- `shuffle` is Fisher–Yates descending: `for i = n-1..1: j = floor(rng()*(i+1)); swap` (generator.ts:30-37). `pick(items, rng) = items[floor(rng()*items.length)]` (generator.ts:39-41).

**Seeded RNG (rng.ts)** — Solo uses `Math.random`; only Battle needs repeatability (rng.ts:1-9).
- `hashString` = **xmur3** (rng.ts:12-21): `h = 1779033703 ^ str.length`; per char: `h = Math.imul(h ^ str.charCodeAt(i), 3432918353); h = (h << 13) | (h >>> 19)` (rotl 13 on 32-bit); finalize: `h = imul(h ^ (h>>>16), 2246822507); h = imul(h ^ (h>>>13), 3266489909); return (h ^= h >>> 16) >>> 0` (unsigned 32-bit).
- `seededRng(seed)` = **mulberry32** (rng.ts:28-36): `state = hashString(seed)`; each call: `state = (state + 0x6d2b79f5) | 0` (wrapping int32 add); `t = imul(state ^ (state >>> 15), 1 | state)`; `t = (t + imul(t ^ (t >>> 7), 61 | t)) ^ t` (the `+` is float64 addition of two int32s, then `^` re-truncates to int32 — equivalent to a wrapping 32-bit add followed by xor); `return ((t ^ (t >>> 14)) >>> 0) / 4294967296` — a double in [0,1) with exactly 32 bits of entropy. Swift equivalent: all ops on UInt32/Int32 with `&+`/`&*`; final `Double(u) * 0x1p-32` is exact.
- `randomSeed()` — 12 chars base-36 via Math.random, minted only by the host (rng.ts:40-46).

**What must be bit-exact for two clients to grow identical deals from one seed:**
1. xmur3 over UTF-16 code units (`charCodeAt`) — seeds in practice are ASCII (`[0-9a-z]{12}` plus composite `"<seed>/attacks/<selfId>"`, src/App.tsx:755-758), so UTF-8 bytes == code units, but the port should use UTF-16 code units to be safe.
2. Math.imul semantics: low 32 bits of the product, interpreted signed (Swift: `Int32(bitPattern: a &* b)` on UInt32). `>>>` = logical shift on the unsigned reinterpretation; `<<`/`|`/`^` = int32 ops; `| 0` = wrap to int32.
3. Float ops: `floor(rng() * n)` for pick/shuffle indices and `rng() < 0.5` for direction — IEEE-754 double semantics (Swift Double matches).
4. **Exact rng consumption order**, including on failure paths (a missing-candidates failure consumes 1 draw, a wrong-length failure 2, a canPlace/span failure 4 — generator.ts:143-198).
5. **Iteration order of `Object.keys(grid)`** for anchor selection (generator.ts:147, 307, 313), of `Object.values(solution)` for the letter shuffle (generator.ts:459), of `Object.keys(built.grid).filter(...)` for extend letters (generator.ts:388-390), and of `Object.entries` in `normalize` (generator.ts:214). All keys contain a comma so none are array-index-like → JS gives pure **insertion order**. A Swift port MUST replace dictionaries with an order-preserving structure (e.g. dictionary + insertion-ordered key array) for anything the RNG indexes into.
6. Word-pool order (COMMON_WORDS file order) and `new Set(word)` first-occurrence letter order feeding byLetter buckets (generator.ts:439-450).
7. Attempt/failure caps: 100/400 build attempts, 500 build failures, 200 extend attempts, 800 extend failures, 200 fallback attempts.

**Battle tile stream (battle.ts:119-169)**: `createTileStream(seed, wordPool = COMMON_WORDS)` wraps `seededRng(seed)`. First `next(count)` generates the opening puzzle with `generatePuzzle(wordPool, max(count, STREAM_CHUNK=5), rng)` and keeps its solution as a private hidden board; thereafter it always extends the hidden board by exactly `STREAM_CHUNK = 5` tiles per `extendPuzzle(hidden, boardBounds(hidden), wordPool, 5, rng)` call until `pending` covers the request, then `splice`s off `count` letters (battle.ts:146-168). Contract: same seed ⇒ same opening batch and thereafter the identical letter *sequence* regardless of how requests are sized (battle.ts:139-144; tests battle.test.ts:45-90 including interleaved request sizes [5,8,5,10,8] vs [8,5,5,8,10]). Tiles are never sent over the wire — every client regrows the deal (battle.ts:14-17). App wiring: shared stream `createTileStream(seed)`, opening deal `stream.next(BATTLE_START_TILES)`; a per-player attack stream is seeded `"${seed}/attacks/${selfId}"` (src/App.tsx:754-762).

Shares always sum exactly to the attack (a 1-tile attack still lands; with 1 rival the whole attack lands on them) — the room never scales the total up (modes.ts:279-292; tests modes.test.ts:250-293 incl. negative count → all-zero shares, NaN → []).

## 6. Sounds (sounds.ts) — synthesis spec for AVAudioEngine

No samples; every sound is oscillators built through Web Audio (sounds.ts:1-5). A **Blip** = `{freq (start Hz), to? (Hz to slide to), at (s offset from sound start), dur (s), gain (0-1 peak), type? (oscillator waveform, default 'sine')}` (sounds.ts:39-52).

Per-blip playback (playSound, sounds.ts:169-192): scheduling starts at `currentTime + 0.01` (avoid clipped attack); for each blip: oscillator of `blip.type ?? 'sine'`; `frequency.setValueAtTime(freq, from)`; if `to` set, `frequency.exponentialRampToValueAtTime(to, from+dur)` (exponential glide over the full duration); **amplitude envelope**: gain 0 at `from`, `linearRampToValueAtTime(gain, from + 0.008)` (8 ms linear attack), `exponentialRampToValueAtTime(0.0001, from + dur)` (exponential decay to −80 dB at the end); oscillator started at `from`, stopped at `from + dur + 0.02`. Connected osc → gain → destination.

Voice table (sounds.ts:54-93), all freqs Hz, times s:
- **tick** (round countdown): 1× square, 1040 Hz, at 0, dur 0.035, gain 0.05.
- **deal** (tiles arriving): 3× triangle rising — 523 @0 dur .09 g.12; 659 @.055 dur .09 g.12; 784 @.11 dur .16 g.12.
- **attack** (rival tiles landing): sawtooth 330→145 Hz @0 dur .3 g.14; square 220→98 Hz @.05 dur .3 g.09 (both exponential downward glides).
- **commit** (word placed): triangle 660 @0 dur .05 g.13; triangle 990 @.035 dur .1 g.10.
- **overflow** (pile over limit): square 466 @0 dur .11 g.15; square 370 @.13 dur .16 g.15 (two-tone alarm, second lower).
- **lose**: triangle 392 @0 dur .16 g.14; triangle 311 @.15 dur .16 g.14; triangle 262 @.3 dur .16 g.14; sawtooth 196 @.45 dur .5 g.15 (four notes falling, last ringing).
- **win**: triangle 523 @0 dur .13 g.13; 659 @.1 dur .13 g.13; 784 @.2 dur .13 g.13; 1047 @.3 dur .45 g.14 (same shape climbing, octave up at the end).

Browser plumbing (irrelevant to Swift but explains the API): lazy AudioContext with webkit fallback, never built while muted (sounds.ts:110-123); `wake()` resumes a suspended context (sounds.ts:125-129); `primeSound()` opens the context on the first pointerdown/keydown gesture (sounds.ts:154-166); `soundEnabled`/`setSoundEnabled` persist to `nana.sound.v1` and wake on enable (sounds.ts:131-145).

## 8. Placement Engine (placement.ts)

- `GAP = -1` rack index sentinel (placement.ts:5).
- `planPlacement(board, size, anchor, dir, picks)` (placement.ts:52-88): walks from anchor in dir; occupied cells are **flowed over** (contribute their letter, consume no pick); a letter pick lands on the first free cell; a gap pick claims exactly the current square — if empty it's recorded in `unfilledGaps` (word still laid out around it for aiming) — then advances. `complete` = all picks consumed && no unfilled gaps. Running off the grid leaves the plan incomplete with only the fitted steps.
- `anchorForGapTarget(board, size, target, dir, picks)` (placement.ts:105-130): computes where the word must start so its FIRST gap lands on a clicked cell; walks backwards — letters before the gap flow back over occupied squares, except the square immediately before the gap must itself be free; null if no gap, a needed square is taken, or the walk leaves the grid.
- `planWordCells(board, size, length, own, dir, start)` (placement.ts:141-160): cells a whole word would occupy if moved/rotated; `own` cells count as free (word vacates them); null on off-grid or collision with another word.
- `startableDirections(board, size, cell)` (placement.ts:176-188): empty cell → both directions (even hard against the edge); occupied cell → only directions whose immediate next cell is in-bounds and free; fully walled → [].
- `impliedDirections(board, cell)` (placement.ts:197-203): letter to the left implies 'across'; letter above implies 'down' (order: across then down).
- `cursorCell(board, size, anchor, dir, picks)` (placement.ts:212-241): the cell the next typed letter lands on, following planPlacement's walk (jumps over existing words; a gap holds its square covered or not); null once off-grid.
- `findAvailable(rack, letter, taken)` (placement.ts:247-257): first rack index whose letter case-insensitively matches and isn't already claimed; −1 if none.

- `scriptedPlacement(board, bounds, step, rack)` (tutorial.ts:119-144): what Skip uses. Empty board → center the word ("row = floor((minRow+maxRow)/2)", col centered minus half word length) laid across; otherwise sweep every cell row-major, trying 'across' then 'down', returning the first fit; null when nowhere fits (caller advances the step without playing). Because each step's deal is short of the crossing letters, the sweep can only land on crossings (tutorial.ts:110-117). Notably it will finish a word the player half-placed (tutorial.test.ts:87-95) and refuses placements that would bury the word inside a longer run (tutorial.test.ts:112-124).
- Onboarding flags (onboarding.ts): one-way "seen" notes — tutorial once ever, one explainer per door; failed reads report "not seen" so the note shows again (onboarding.ts:1-11).

## RISKS
- JS object key insertion order is load-bearing for battle determinism: Object.keys/values on TileMaps feed rng-indexed picks (generator.ts:147,307,388,459). Swift Dictionary iteration order is unspecified and varies per-process (hash seeding) - port must pair the map with an insertion-ordered key list or the same seed will deal different letters than web clients.
- Bit-exact RNG required: Math.imul (signed low-32 multiply), (x|0) wrap, >>> unsigned shifts, rotl via (h<<13)|(h>>>19), and a float64 addition that acts as a wrapping 32-bit add in mulberry32 (rng.ts:12-36). Use UInt32/Int32 with &+ / &* and Double(u) * 0x1p-32; validate against JS-generated vectors.
- xmur3 hashes UTF-16 code units (charCodeAt). Current seeds are ASCII (host seed [0-9a-z]{12}, composite 'seed/attacks/selfId'), but hashing UTF-8 bytes would diverge on any non-ASCII input - hash code units, not bytes.
- Exact rng draw counts on generator failure paths matter (1 draw for missing candidates, 2 for wrong length, 4 for canPlace/span rejection, generator.ts:143-198); refactoring the control flow even slightly desynchronizes clients.
- JS Array.prototype.sort is stable (ES2019); Swift's sort() is not guaranteed stable. components() tie order (board.ts:109) decides which equal-size group is 'main' vs disconnected, and rankByElimination (battle.ts:234) relies on stable order for equal outOrder - add explicit tiebreakers or a stable sort.
- Math.round is half-up toward +infinity in JS (modes.ts:276): 4.5 -> 5. Swift .rounded() (half away from zero) matches for the non-negative growth values that occur, but .toNearestOrEven / lround differences would break the attack table (test expects battleAttackTiles(6,2)=5).
- COMMON_WORDS order comes from common-words.txt line order via a Vite '?raw' import (commonWords.ts:1-8); any re-sorting, dedup, or normalization during embedding changes byLetter/byLength bucket order and breaks cross-platform deals.
- byLetter buckets iterate 'new Set(word)' - letter order is first occurrence within the word (generator.ts:377,442). A Swift Set<Character> is unordered; must preserve first-occurrence order explicitly.
- generatePuzzle/extendPuzzle default to Math.random and are also called with the seeded rng; the Swift API should keep rng injectable rather than baking in one source.
- battle.ts is not fully pure: battleLink uses window.location (battle.ts:107); codeFromHash parses '#battle=CODE' URLs - needs a deep-link equivalent.
- sounds.ts exponentialRampToValueAtTime cannot ramp to/from 0 (hence 0.0001 floor and setValueAtTime(0)+linear 8ms attack); AVAudioEngine has no direct param-ramp equivalent - recreate the envelope by rendering the gain curve (exponential decay = multiplicative per-sample factor) or via scheduled parameter events.
- Dictionary is fetched at runtime (dictionary.ts:10-16, App.tsx:1002) and parse trims/lowercases each line; the file already contains 2-letter words (min length 2) which validateBoard rejects independently via MIN_WORD_LENGTH - don't pre-filter the file or membership semantics stay the same but golden fixtures of the Set size change.
- localStorage failure semantics are deliberate: blocked reads mean 'defaults / not seen' (onboarding shows notes again, sound defaults ON, stats start at zero) and writes silently drop (setups.ts:43-49, stats.ts:68-73, onboarding.ts:29-56, sounds.ts:95-103) - mirror this rather than throwing.
- Generator tests are statistical (50-iteration loops on Math.random) and assert the crossword builder 'essentially always' succeeds with the 5,000-word pool (generator.test.ts:22-25); a Swift port with subtly different retry behavior could pass rarely-failing runs - keep the same attempt/failure caps and pool.
- splitAttackTiles handles negative and NaN counts specially (negative -> all-zero shares of length targets, NaN -> [], targets<=0 -> []) and normalizes negative 'from' with double-mod (modes.ts:293-302); Swift % on negatives differs from the manual normalization - port the expression literally.
- parseKey splits on the FIRST comma and Number() parses the halves (types.ts:53-56); keys are ints (possibly negative) - a Swift coordinate struct is cleaner but any string round-trip used for serialization must keep the exact 'row,col' format for save/wire compatibility.
